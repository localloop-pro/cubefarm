# Before/after evidence for UI pull requests

Use this checklist when a pull request changes visible UI. CubeFarm's QA flow already captures screenshots and posts them in a PR comment through its `swarm-qa-evidence` branch. Keep that as the normal evidence path; this guide makes the comparison easier to trust.

1. **Pick the claim.** Name the screen, action, and expected visual change. Record the before revision and the exact PR head commit tested. Capture the before state from the base revision and the after state from the PR head; state any environment or data differences.
2. **Match the scene.** Use the same viewport size, zoom, route, test data, login role, browser state, and interaction step for each pair. Capture desktop and phone sizes when relevant. Include important states such as errors, empty content, keyboard focus, or a dialog when they bear on the change. Reuse existing PNGs only if their revision, scenario, and viewport are known and still match; otherwise take new captures.
3. **Protect the image.** Inspect every frame before publishing. Remove credentials, tokens, customer or other private data, and sensitive URL parameters. Do not send such images to public hosts. A custom upload URL does not make storage private by itself; use only an approved destination with suitable access controls. Prefer CubeFarm's existing evidence path when it meets the project's access requirements.
4. **Report the result.** Put each pair side by side or link both images with clear *Before* and *After* labels. State the scenario, viewport, before revision, tested commit, and where the images came from. Mark each check **pass**, **fail**, or **skipped**, with the reason and any limits. Screenshots show appearance; also report relevant keyboard, screen-reader, contrast, or other accessibility checks separately. Do not call an untested check a pass.

The [current Vercel before-and-after project](https://github.com/vercel-labs/before-and-after) can format **existing local images** into a PR comparison. Its current workflow uses `agent-browser` for capture, `skill/scripts/format.mjs` for Markdown, and GitHub CLI attachments for publication. Formatting Markdown does not upload images; attaching them to a PR does. Follow the [version-matched upstream instructions](https://github.com/vercel-labs/before-and-after/blob/main/skill/SKILL.md) if you choose that optional path, and review both the images and destination before any upload. Do not assume older `@vercel/before-and-after --markdown`, `--upload-url`, or `0x0.st` instructions describe the current project.

If a browser reports “No usable sandbox,” keep its normal sandbox enabled. Do not disable browser sandboxing as a default or automatic fix. Only consider that change in an approved isolated runtime after reviewing the security cost; otherwise mark the visual check skipped and explain why.
